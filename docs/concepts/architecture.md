# Архитектура без церемоний

DDD в DDF — способ сделать бизнес-код понятным и тестируемым, а не набор обязательных классов. Берите только те паттерны, которые решают текущую проблему.

## Зависимости направлены к домену

```text
presentation ──► application ──► domain
                     │
                     ▼
               Protocol / port
                     ▲
                     │
              infrastructure
```

`application` знает контракт `Repository`, но не `AsyncSession`; `infrastructure` реализует этот контракт через `SqlAlchemyRepository`. В тесте вместо базы можно подставить простую реализацию в памяти.

## Агрегат — граница согласованности

Агрегат объединяет объекты, которые обязаны оставаться согласованными в одной операции. Его корень наследует `AggregateRoot` и владеет изменением внутреннего состояния.

Не превращайте агрегат в «всю предметную область». Например, заказ и платёж могут ссылаться друг на друга по идентификатору, но подтверждение платежа не обязано грузить все заказы клиента. Маленькая транзакционная граница обычно проще масштабируется и конкурирует за меньшее число блокировок.

## Pythonic, а не Java-подход

| Вместо | В DDF |
| --- | --- |
| абстрактных классов ради интерфейса | структурные контракты `Protocol` |
| фабрики для каждого объекта | явные `dataclass` и функции-конструкторы |
| getter/setter для каждого поля | методы там, где есть инвариант или поведение |
| один «Service» на всё | небольшие use case и функции |

Инкапсуляция в Python — это не обязательные приватные поля. Важнее, чтобы правила изменения были собраны рядом с состоянием, а внешние слои не повторяли их по-своему.

## Composition root

Единственное место, где допустимо собрать конкретные адаптеры, — точка запуска приложения: FastAPI dependency, CLI bootstrap или воркер. Там создаются сессия SQLAlchemy, репозиторий, кэш и publisher. Остальной код принимает их через аргументы.

!!! example "Проверка без инфраструктуры"

    `Task(title="Написать документацию").complete()` можно проверить обычным unit-тестом без event loop, PostgreSQL и HTTP. Это хороший признак того, что правило лежит в домене.
