# Кэширование

Кэш в DDF — инфраструктурная оптимизация, а не второй источник истины. Контракт `Cache[T]` содержит `get`, `set`, `delete`, `exists`; конкретная политика располагается в адаптере или декораторе репозитория.

## Cache-aside с репозиторием

`CachedRepository` оборачивает любой `Repository`.

```text
read(id)   cache hit  ──► вернуть объект
           cache miss ──► repository.read ──► cache.set ──► вернуть объект

update/delete ──► repository ──► cache.delete
```

При `create` декоратор сохраняет объект и кладёт его в кэш. При обновлении он инвалидирует ключ: следующее чтение загрузит актуальный снимок из базы. `exists()` сознательно идёт в источник истины.

```python
from ddf.infra.cache.cached_repository import CachedRepository
from ddf.infra.cache.redis.redis_cache import RedisCache
from ddf.infra.cache.redis.serializers import OrJsonSerializer

cache = RedisCache(redis, OrJsonSerializer(User), ttl=300)
users = CachedRepository(sql_users, cache, prefix="user")
```

Ключ имеет вид `<prefix>:<uuid>`, например `user:019...`. Давайте prefix по bounded context, чтобы `user` из identity не пересёкся с `user` из CRM.

## Адаптеры

| Адаптер | Когда использовать | Особенность |
| --- | --- | --- |
| `InMemoryCache` | тесты, один процесс, локальная разработка | TTL и ленивое удаление, данные не разделяются между процессами |
| `RedisCache` | несколько экземпляров приложения | сериализатор и общий TTL передаются явно |
| `MultiLevelCache` | горячие ключи и Redis | на попадании в дальний уровень прогревает предыдущие |

`InMemoryCache.start()` запускает периодическую очистку; при остановке приложения вызовите `await close()`. Его `exists()` проверяет наличие ключа без немедленной проверки TTL, поэтому для точного результата используйте `get()`.

## Сериализация

`OrJsonSerializer` хранит читаемый JSON, `MsgpackSerializer` — более компактный бинарный формат. Оба используют Pydantic `TypeAdapter`, чтобы восстановить целевой тип после чтения.

Выбирайте JSON, когда важны отладка и совместимость; MessagePack — когда измерения показали значимую экономию памяти или сети. Не кэшируйте Python-объекты через pickle: это небезопасно для недоверенных данных и связывает формат с кодом.

!!! warning "Кэш возвращает снимок"

    После `read()` не меняйте агрегат «в памяти» в ожидании, что это сохранится. Сначала выполните use case и сохранение через репозиторий. В распределённой системе всё равно возможны краткие устаревшие чтения — TTL и инвалидация уменьшают окно, но не создают строгую консистентность.
