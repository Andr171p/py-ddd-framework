# 0004. Публиковать доменные события после commit

**Статус:** Принято
**Дата:** 2026-09-17

## Контекст

Потребитель события `InvoicePaid` ожидает, что счёт уже существует в базе в согласованном состоянии. Публикация до commit может сообщить о факте, который затем откатится. Прямое связывание домена с брокером делает правила нетестируемыми и смешивает слои.

## Решение

Агрегат только накапливает `Event`. `EventDispatcher` извлекает их, при наличии `EventStore` записывает, затем вызывает `UnitOfWork.commit()` и только после успеха передаёт пачку publisher-у.

## Последствия

- Брокер не получает сообщение о транзакции, которая не закоммичена.
- Домен не зависит от RabbitMQ/FastStream.
- Остаётся окно отказа между commit и publish; семантика не является exactly-once.
- Критичные интеграции должны использовать transactional outbox, повторную доставку и идемпотентных потребителей.

## Альтернативы

- **Publish до commit:** уменьшает окно потери, но допускает ложные события.
- **Двухфазная транзакция БД+брокер:** сложна в эксплуатации и обычно не стоит цены для микросервисов.
- **Outbox:** рекомендуемое усиление текущей схемы, которое требует реализации worker-а и хранилища.
