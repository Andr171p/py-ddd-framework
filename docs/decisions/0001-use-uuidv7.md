# 0001. Использовать UUIDv7 для идентичности сущностей

**Статус:** Принято
**Дата:** 2026-09-17

## Контекст

Сущностям нужен идентификатор, который можно создать до записи в БД, безопасно использовать в распределённых сервисах и эффективно индексировать. Случайный UUID4 удовлетворяет первым двум требованиям, но его случайный порядок создаёт менее локальные вставки в B-tree индекс. Автоинкрементный integer удобен в одной БД, но раскрывает объём данных и хуже подходит для автономного создания объектов.

## Решение

Базовые `Entity` и SQLAlchemy `Base` используют UUIDv7. В Python ID создаётся через `uuid.uuid7()`, в БД задан server default `uuid_generate_v7()`.

UUIDv7 содержит временную компоненту и при естественном сравнении приблизительно следует времени генерации. В интеграции SQLAlchemy он также служит курсором по умолчанию.

## Последствия

- Идентификатор известен до `flush` и его можно включить в доменное событие.
- Последовательные вставки и cursor-пагинация получают более естественный порядок, чем с UUID4.
- API и внешние ключи используют UUID, а не числовой surrogate key.
- Требуется Python 3.14+ и поддержка `uuid_generate_v7()` в PostgreSQL либо эквивалентная миграционная стратегия.
- Временной порядок UUIDv7 не заменяет бизнес-время и не является абсолютной глобальной последовательностью при нескольких генераторах.

## Альтернативы

- **UUID4:** широко доступен, но не упорядочен по времени.
- **BIGINT identity:** компактен и прост для одной базы, но хуже для распределённого создания и предсказуем снаружи.
- **ULID:** также сортируем по времени, но потребует сторонней библиотеки и отличного от стандартного `uuid.UUID` типа.
