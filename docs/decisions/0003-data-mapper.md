# 0003. Отделить доменную модель от ORM через Data Mapper

**Статус:** Принято
**Дата:** 2026-09-17

## Контекст

ORM-модель одновременно отражает таблицу, жизненный цикл сессии, ленивые связи и технические ограничения. Если сделать её доменной сущностью, правила начинают зависеть от SQLAlchemy, а изменение схемы хранения расползается в прикладной код.

## Решение

SQLAlchemy-модель наследуется от инфраструктурного `Base`. Каждый репозиторий задаёт `DataMapper`, переводящий ORM-модель в доменную и обратно. `SqlAlchemyRepository` работает с mapper-ом, но прикладной слой видит только `Repository[EntityT]`.

## Последствия

- Домен можно тестировать и использовать без SQLAlchemy.
- Преобразования Value Object и несовпадающих полей сосредоточены в одном месте.
- Есть дополнительный код и стоимость преобразования на чтении/записи.
- Mapper нужно покрывать round-trip тестами; нельзя забывать новые значимые поля.

## Альтернативы

- **Active Record:** меньше кода, но сильная связь домена с ORM.
- **Pydantic/ORM одна модель:** удобно для простого API, но слабо выражает инварианты и persistence-границу.
