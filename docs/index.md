# DDF

**DDF** — набор небольших, типизированных строительных блоков для Python-приложений с предметной областью. Он помогает выразить доменную модель, отделить её от хранения данных и подключить повторяющиеся прикладные механизмы: репозитории, события, пагинацию, фильтрацию и кэш.

Фреймворк не диктует «папки ради DDD» и не пытается перенести Java-паттерны в Python. Доменный объект — обычный `dataclass`, контракт — `Protocol`, а интеграции остаются заменяемыми адаптерами.

## Когда DDF подходит

- В сервисе есть бизнес-правила, которые неудобно держать в HTTP-обработчиках или ORM-моделях.
- Одни и те же подходы к выборкам, пагинации, событиям и кэшу повторяются между проектами.
- Нужны асинхронный SQLAlchemy, FastAPI и возможность заменить инфраструктуру в тестах.

Если приложение — небольшой CRUD без заметной предметной логики, начинайте с простых Pydantic-схем и SQLAlchemy. Вводите DDF там, где появляется реальная граница между бизнес-смыслом и деталями доставки/хранения.

## Основная идея

```text
HTTP / CLI / consumer
        │ DTO
        ▼
  application ───────────────► Repository (Protocol)
   │     │                            │
   │     └── Domain events            ▼
   ▼                           SQLAlchemy / cache / broker
domain
```

Направление зависимостей — внутрь: домен не импортирует FastAPI, SQLAlchemy, Redis или RabbitMQ. Прикладной слой зависит от абстракций, а инфраструктура их реализует.

## Что есть в текущей версии

- `Entity` и `AggregateRoot` с UUIDv7, отметками времени и очередью доменных событий;
- `Repository` и `UnitOfWork` как асинхронные контракты;
- базовый `Crud` для типовых use case с точками расширения;
- SQLAlchemy-репозиторий, Data Mapper, DSL-фильтры, offset- и cursor-пагинация;
- cache-aside, память/Redis и многоуровневый кэш;
- диспетчер доменных событий и адаптер RabbitMQ.
